# Mono 로드맵 — v1.0 까지

기준일 **2026-09-10** · 최신 태그 **v0.1.13** · 작업 브랜치 `cursor/avalonia-native-control`

이 문서는 "무엇을 더 만들까"가 아니라 **"무엇이 확인되면 1.0 이라 부를 수 있는가"** 를 적는다.
[`03-구현현황.md`](03-구현현황.md) 기준으로 기능표는 거의 다 찼다. 그래서 남은 일의 **성격**이 바뀌었다 —
코드를 더 쓰는 일보다 **실측 · 계약 · 서명**처럼 코드 바깥에서 시간이 드는 일이 임계 경로에 있다.

날짜를 박지 않는다. 1인 개발의 가용 시간을 모르는 상태에서 날짜는 지어낸 숫자가 된다.
대신 **순서 · 규모 · 나가는 조건(게이트)** 으로 적는다. 게이트를 통과했는지는 사람이 아니라 로그와 측정값이 답한다.

## 0. 지금 어디에 있나

| 축 | 상태 |
| --- | --- |
| 기능 폭 | ✅ 기획서 기능표 대부분 Core·GUI 양쪽 도달 가능 (선언 커맨드 89개 중 88개 도달 확인, 나머지 1개는 죽은 코드라 삭제) |

| 외부 의존 | ⬜ Tidal/Qobuz 파트너 키 미발급 (현재 데모 카탈로그) · 코드 서명 인증서 미구매 |

최근 5개 커밋이 전부 하나의 이야기다 — **"비트퍼펙트라고 표시되는데 실제로는 아니었다"** 를 잡는 과정.
조용한 Shared 강등을 없앴고, NAudio 가 배타 모드에서도 끼워 넣던 DMO 리샘플러를 거부했고,
ASIO 지연 단위(샘플↔ms) 를 고쳤고, ASIO 콜백 크래시를 STA + float32 로 막았다.
**이 흐름이 끝나지 않은 채로 다음 단계를 시작하면 안 된다.** 1.0 의 값어치는 여기서 나온다.

## 2. 마일스톤 상세

### M1 — 0.2.x · 소리가 흔들리지 않는다

모듈 1 을 "착수"에서 "마감"으로 옮긴다. 지금 열려 있는 실패들이 대상이다.

- **ASIO 안정화.** NAudio `AsioOut` 이 콜백 안에서 죽는 문제는 float32 + STA 로 한 번 막았다.
  다음 라운드에서 또 죽으면 **NAudio 의존을 걷어내고 ASIO SDK 를 직접 바인딩할지** 결정한다.
  판단 기준: 워치독 재기동이 재발하는가. 재발하면 우회가 아니라 교체다.
- **언더런 0.** 백프레셔 천장 ≤ 장치 큐 용량 불변식은 세웠다. 이제 장시간(2시간+) 연속 재생에서
  `drop=0 resync=0` 을 로그로 확인한다. 한 번이라도 깨지면 그 로그가 다음 작업 지시다.
- **포맷 매트릭스.** 44.1/48/88.2/96/176.4/192/352.8/384 × 16/24/32 × (WASAPI 배타 · ASIO · 공유)
  조합을 자동 스모크로 돌린다. 지금은 사람이 한 조합씩 만난다.
- **DSD 경로.** DoP / 네이티브 DSD 를 실제 DAC 에 낸다. 코드에는 있고 소리로 확인된 적이 없다.
- **실패의 언어.** 점유 실패·포맷 거부·장치 분리 각각이 사용자에게 **무엇을 하라고** 말하는지 문구를 확정한다.
  (이미 [다시 시도]·[장치 설정으로 이동] 팝업은 있다. 사유 문구가 아직 개발자 말투다.)

**나가는 조건** — 서로 다른 3개 장치(내장 코덱 · USB DAC · RME 급 인터페이스)에서
각 30분 연속 재생, `drop=0`, 크래시 0, 배타 실패 시 사용자가 스스로 빠져나옴.

### M2 — 0.3.x · 측정이 말한다

`03-구현현황.md` §5 의 🟡 를 ✅ 로 바꾸는 단계. **코드가 아니라 숫자를 만드는 일이다.**

- **LAN 2기기 실측.** 서로 다른 PC 의 Output 두 대에서 `sync_probe` 의 `meetsTarget=true`.
  같은 호스트에서 offset −0.16ms / jitter 0.33ms 는 이미 나왔다. 이건 반쪽 증거다.
- **WAN 락 유지.** 목표는 5ms 가 아니라 **끊기지 않는 것**(20–80ms 적응형). 버퍼가 풀렸을 때 리싱크가
  가청 사고 없이 일어나는지 본다.
- **소셜 부하 격리 증명.** 채팅·핀·반응을 최대로 때리면서 오디오 콜백 지터가 변하지 않음을 측정한다.
  "설계상 분리되어 있다"는 주장이지 측정이 아니다.
- **측정 UI.** 시그널 패스 팝오버에 offset·jitter 는 있다. 여기에 **측정 리포트 내보내기**를 붙인다 —
  테스터가 스크린샷 대신 파일을 준다.

**나가는 조건** — 2기기 LAN `meetsTarget=true` 로그 · 소셜 최대 부하에서 지터 변화 없음이 그래프로 남음.

### M3 — 0.4.x · 설치가 무섭지 않다

- **코드 서명.** `publish.ps1` 은 `MONO_SIGN_PFX_BASE64` 시크릿을 이미 받는다. **인증서만 없다.**
  OV 는 SmartScreen 평판을 쌓아야 하고 EV 는 즉시 통과한다 — 초기 배포량이 적으므로 **EV 권장**.
- **자동 업데이트 확인.** `publish/releases` 에 Squirrel 계열 산출물(`RELEASES` · `.nupkg`)이 이미 있다.
  0.1.x → 0.2.x 실제 업데이트 경로를 한 번 끝까지 돌린다. 서명 후에는 서명된 것끼리 다시 돌린다.
- **방화벽 첫 만남.** 7700 · 7701 허용 대화상자가 언제 뜨는지, 거부했을 때 앱이 무엇을 말하는지 정한다.
- **`사용법.txt` 와 실제 zip 일치.** [`04-UIUX기획서`](04-UIUX기획서.md) §5.3 규약대로 `wwwroot`·`Run-*.bat`·CLI 가
  출시 zip 에 없는지 파이프라인에서 검사한다(사람이 매번 확인할 일이 아니다).

**나가는 조건** — 깨끗한 Windows VM 에서 다운로드 → 설치 → 첫 소리까지 **경고 창 없이**, 터미널 0개.

### M4 — 0.5.x · 화면을 사람이 본다

`03-구현현황.md` §6-6 이 정직하게 남겨 둔 구멍이다. 빌드와 프로토콜은 확인했지만 **레이아웃은 아무도 안 봤다.**

- **전 화면 육안 검증.** 사이드바 15개 항목 × 라이트/다크 × 창 크기 3종. 스크린샷을 `docs/assets/` 에 남긴다.
- **빈 상태 · 긴 문자열 · 실패 상태.** 라이브러리 0곡, 아티스트명 60자, Core 연결 끊김 — 세 가지가 제일 잘 깨진다.
- **세션 보존 기간 UI** (§4 의 🟡). Core 는 이미 집행한다. GUI 에서 값을 바꿀 수 있게 한다.
- **P1 기능** — [`01-기획명세서`](01-기획명세서.md) 가 P1 로 표시해 둔 것:
  - **Easy EQ**: Parametric 기본 + 초보용 Graphic 모드, 커브 상호 반영
  - **Crossfeed**: 프리셋으로만 동작 중 → 강도 조절 UI
- **앨범 아트 60fps.** 목표는 적혀 있고 측정된 적은 없다. 대형 그리드 스크롤 프레임타임을 잰다.

**나가는 조건** — 15개 화면 스크린샷이 문서에 있고, 깨진 레이아웃 0개.

### M5 — 0.6.x · 스트리밍이 진짜다

- Tidal / Qobuz **파트너 키 발급 후** 실 OAuth 로그인 → 실 카탈로그 → 실 재생.
- 라이선스 분기 실동작 확인: 스트리밍은 **Clock-sync**(각자 재생), 팬아웃은 **로컬 파일 한정**.
  이 경계가 코드에서 뚫리지 않는지 테스트로 고정한다.
- 로컬/스트리밍 동일 앨범 병합 표시(`Local+Stream` 배지)를 실 카탈로그에서 재확인.
- 미구독·지역 제한·토큰 만료 세 가지 실패를 사용자 언어로 처리.

**나가는 조건** — 실 계정으로 로그인 → 큐에 넣기 → 라운지에서 2인 동시 청취.

### M6 — 0.9.x · 남이 써 본다

- **QA 도구 정착.** `tools/mono-qa/` (Vercel Blob 기반 체크리스트 수집)를 커밋하고 배포한다.
  지금은 테스터 피드백이 로그 파일과 대화로 온다 — 그게 이번 오디오 버그들을 잡아 준 경로이므로 **구조화할 값어치가 있다.**
- **웹사이트 공개.** `site/` 7페이지(index · sound · experience · compatibility · core · how-it-works · download)를
  커밋하고 다운로드 페이지를 릴리스에 연결한다.
- **테스터 5~10명.** 장치 다양성이 목적이다 — 내장 코덱 / 저가 USB DAC / 프로 인터페이스 / DSD DAC 최소 1대씩.
- **크래시·로그 수집 경로.** 사용자가 로그를 첨부하는 방법이 GUI 안에 있어야 한다.
- **다국어 표기 정리.** UI 는 한국어, 제품명·배지는 영문 — 지금 섞여 있는 부분을 한 번 훑는다.

**나가는 조건** — 외부 테스터 2주 · 신규 P0 결함 0.

## 3. 지금 당장 병렬로 시작할 것 (리드타임 항목)

**M3·M5 는 순서상 중간이지만, 신청은 오늘 한다.** 코드가 끝나고 신청하면 그만큼 1.0 이 밀린다.

| 항목 | 왜 지금 | 리드타임 | 막히면 |
| --- | --- | --- | --- |
| **코드 서명 인증서(EV)** | 조직 검증에 서류·통화가 필요하다. 코드와 무관하게 대기 시간이 있다 | 수일~수주 | 서명 없는 0.9 베타는 가능. 1.0 은 불가 |
| **Tidal / Qobuz 파트너 키** | 승인 여부가 우리 손에 없다. 거절되거나 무응답일 수 있다 | 수주~ | **1.0 에서 스트리밍을 뺀다.** 로컬 라이브러리만으로 1.0 을 내고 스트리밍은 1.1 로 — 이 결정을 M5 전에 내린다 |
| **테스트 장비** | ASIO·DSD 실측은 물건이 있어야 한다. RME 는 테스터가 갖고 있고 DSD DAC 은 아직 없다 | 구매/대여 | DoP 만 검증하고 네이티브 DSD 는 1.0 범위에서 제외 명시 |

세 항목 모두 **"안 되면 무엇을 뺄지"를 미리 정해 뒀다.** 로드맵이 외부 승인에 인질로 잡히지 않게 하는 장치다.

## 5. v1.0 이후

지금 결정할 필요는 없지만 **1.0 의 구조를 망치지 않기 위해** 방향만 적어 둔다.

**1.1 — 오디오 심화 (기획서 P2)**
- 스마트 룸 보정 (REW 연동 · 측정 장비 없는 사용자용 가이드 모드)
- Speaker Setup (거리·레벨·딜레이)
- Device EQ 디렉터리 (신청 → 검수 → 모델명 검색)

**1.2 — 플랫폼 확장**
- macOS Control (Avalonia 라 경로는 열려 있다. CoreAudio Output 이 실제 일)
- 모바일 Control 네이티브 앱 — 기획서가 "추후"로 남긴 것
- Linux Core 를 NAS/홈서버에 상주

**1.3 — 라운지 성숙**
- 공개 라운지 디렉터리 (지금은 초대 코드만)
- 라디오 DJ 모드 — 타겟에 적혀 있으나 아직 Host Queue 모드로 대체 중
- 세션 하이라이트 공유(식별자·메타만, 파일 재배포 없음)

**해석 주의** — 이 목록은 우선순위가 아니라 **보관함**이다. 1.0 이 나가고 사용자가 무엇을 요구하는지 본 뒤에 순서를 정한다.

## 6. 이 로드맵의 가정

명시해 둔다. 틀리면 로드맵이 바뀐다.

1. **1인 개발이다.** 마일스톤은 병렬이 아니라 직렬로 진행된다. §3 의 외부 신청만 병렬이다.
2. **1.0 의 타깃 플랫폼은 Windows 뿐이다.** macOS·Linux 는 1.2.
3. **"1.0"의 정의는 기능 완성이 아니라 신뢰다.** 남이 설치해서 경고 없이 켜고, 배지가 거짓말하지 않고, 소리가 끊기지 않는 것.
   기능은 이미 충분하다 — 검증이 부족하다.
4. **테스터 로그가 계속 들어온다는 가정.** 최근 오디오 버그 4개를 전부 테스터 로그가 잡아냈다. 이 채널이 끊기면 M1·M2 가 크게 느려진다.
