# Mono — 프로그램 기획 및 기능 구체화 명세서

본 문서는 Mono의 핵심 가치를 정의하고, 사용자 경험을 극대화하기 위한 상세 기능 및 요구사항을 정리한다.
원본 기획서(「프로그램 기획 및 기능 구체화 명세서」, 가칭 "Mono")의 핵심 기능을 반영해 최신화했다 — 반응 히트맵, 스마트 오토플레이, 멀티 디바이스 존, 다국어 검색, 위키백과 이력, UI/UX 가이드가 이번에 추가되었다.

---

## 1. 프로그램 개요 및 구체화 설명

프로그램의 정체성과 사용자에게 제공하고자 하는 핵심 가치를 상세히 기술한다.

### 프로그램 명칭

**Mono**

- 혼자 듣든(Mono-logue) 같이 듣든, 결국 모두가 **하나의 소리(Mono)** 를 공유한다는 의미를 담는다.
- 핵심 태그라인: *"혼자서 음악을 청취하거나, 같이 음악을 청취하거나, 하나의 음악으로 최고의 경험을!"* — *"Alone or together, the ultimate experience through one sound!"*
- 제품군 표기: **Mono Core** / **Mono Control** / **Mono Output**

### 핵심 컨셉

**“오디오파일급 무손실 음질과 실시간 소셜 청음(Co-Listening)이 결합된 하이파이 오디오 라운지”**

Roon의 강력한 Bit-perfect 오디오 전송, 고해상도 DSP, 풍부한 메타데이터 그래프를 유지하면서, 물리적으로 떨어진 유저들이 마치 같은 룸에서 음악을 틀어놓고 이야기하는 듯한 **초저지연 동기화 청음 룸(Hi-Fi Sync Room)** 및 공동 큐레이션 환경을 제공한다.

Mono는 “스트리밍 앱에 채팅을 붙인 것”이 아니라, **Core가 마스터 클럭인 분산 오디오 시스템** 위에 라운지(룸)를 올린 제품이다. 음질 경로와 소셜 경로는 분리되어 설계되며, 소셜 기능이 비트퍼펙트 경로를 오염시키지 않는다.

### 주요 타겟

- 고음질 스트리밍(Tidal, Qobuz 등) 및 무손실 음원(FLAC, DSD) 라이브러리를 보유한 오디오파일(Audiophile) — 혼자서도 최고 음질로 듣되, 즐겁게 감상을 공유하고 싶은 사람.
- 원격으로 친구, 지인들과 음반을 함께 들으며 곡 해설, 감상평, 앨범 아트를 나누고 싶은 음악 애호가.
- 리스닝 파티(Listening Party)나 공동 DJ 세션을 운영하고자 하는 음악 크리에이터 및 큐레이터 — 지인 혹은 공개적으로 청음회를 열고 싶은 사람.
- 멀티 디바이스로 여러 장비를 비교·청음하고 싶은 장비 리뷰어 및 오디오 업체.
- 강화된 메타데이터·다국어 검색으로 같은 아티스트/작곡가의 다양한 음원을 탐색하고 싶은 유저.
- 고음질로 첫 라디오 방송을 진행해보고 싶은 라디오 진행자(DJ).

### 사용자 워크플로우

1. **라이브러리 통합 & 오디오 엔진 설정**  
   로컬 음원(PC/NAS) 및 스트리밍 계정을 연동하고, 출력 DAC/앰프 엔드포인트를 설정한다. Core가 라이브러리 스캔·메타데이터 매칭·DSP 체인을 담당하고, Control은 설정 UI만 제공한다.

2. **오디오 라운지(룸) 생성 또는 참여**  
   개방형 또는 초대 기반의 ‘청음 라운지’를 개설하거나 친구의 세션에 입장한다. 룸 모드는 다음을 포함한다.
   - **Open Lounge**: 공개 입장, 공동 큐
   - **Invite**: 초대 코드/친구만
   - **Host Queue (DJ/큐레이터)**: 호스트만 선곡, 참가자는 감상·코멘트만
   - **Audiophile Mode**: 포맷 고정(Bit-perfect), DSP 잠금, 트랜스코딩 금지, UI는 아트/라이너/파형 중심, 채팅은 접이식

3. **초저지연 동기화 스트리밍 & 공동 큐(Queue) 빌딩**  
   트랙을 큐에 등록하고, 각자의 DAC에서 동기화된 재생을 경험한다. 재생 헤드와 동일한 타임라인에 **가사(LRC/동기화 가사)** 와 큐 포인터가 붙는다.

4. **인터랙티브 감상**  
   앨범 라이너 노트 및 뮤지션 관계도를 함께 열람하고, 타임스탬프 기반 코멘트로 “이 구간이 좋았다”를 공유한다.

5. **세션 아카이빙**  
   파티 종료 시 저장 여부를 질의한다. 동의한 경우 좋았던 곡을 모아 개인 플레이리스트를 만들거나, 청음 히스토리를 통해 곡을 다시 듣거나 공유한다.

## 2. 기능 구체화

프로그램의 구현에 필요한 핵심 기능을 카테고리별로 구분하여 정의한다.

| 구분 | 주요 기능명 | 기능 상세 설명 및 작동 방식 | 비고 |
| --- | --- | --- | --- |
| 핵심 기술 | 초저지연 음원 공유 시스템 | 서로 다른 네트워크의 클라이언트 간 재생 오차를 **목표 5ms 이내**(동일 LAN / 우수 경로)로 제어한다. WAN은 적응형 지터 버퍼로 **락 유지 우선**(일반적으로 20–80ms)이며, 버퍼가 풀리면 리싱크한다. | Core가 마스터 클럭. 상세는 MATP |
| 핵심 기술 | MATP (Mono Audio Transport Protocol) | UPnP/DLNA를 쓰지 않는 독자 TCP 기반 양방향 오디오 전송. 포맷/볼륨/클럭 오프셋을 Core가 실시간 파악. PCM/DSD 페이로드와 컨트롤 플레인을 분리한다. | RAAT 포지션 |
| 핵심 기술 | 마스터 클럭 & 멀티 엔드포인트 동기화 | NTP/PTP 스타일 오프셋 측정 + 재생 타임라인(`media_time` ↔ `wall_clock`). Output은 수신 버퍼를 두고 지정 PTS에 출력한다. | µs급 측정, ms급 가청 락 |
| 핵심 기술 | Bit-perfect 경로 | 소스 비트뎁스/샘플레이트/DSD를 가능한 한 변환 없이 DAC까지 전달. Audiophile Mode에서는 SRC·믹스·볼륨 디지털 감쇠를 기본 금지(하드웨어 볼륨만). | 호환 불가 시 명시적 동의 후 트랜스코드 |
| 핵심 기술 | 고해상도 DSP 파이프라인 | Core에서만 수행: 업샘플, 룸 EQ, 컨볼루션(IR), 헤드폰 크로스피드, DSD↔PCM. Control/채팅 부하는 DSP와 분리된 스레드·프로세스 우선순위로 격리. | 룸별로 DSP 프리셋 잠금 가능 |
| 핵심 기술 | 메타데이터 그래프 | 아티스트–앨범–트랙–크레딧–레이블–시대 관계를 로컬 객체 그래프로 보유. 하이퍼링크 탐색은 클라우드 왕복 없이 Core 로컬 쿼리. | 외부 메타 소스는 백그라운드 매칭 |
| 핵심 기술 | 고성능 로컬 카탈로그 DB | 수만~수십만 곡 메타, 관계, 재생 기록을 로컬에서 즉시 검색. 1차는 SQLite + 인덱스, 그래프 캐시는 메모리. 필요 시 임베디드 KV로 핫패스 이전. | 클라우드 비의존 탐색 |
| 핵심 기술 | 스마트 선택형 오토플레이 | 큐가 끝나갈 때(곡 종료 약 40초 전) 후보 3곡을 제시한다. 무응답 시 1번 후보가 자동 재생되고, 선택하면 그 곡이 재생된다. 방치해도 되고 취향껏 골라도 된다. | 다양하게 듣고 싶은 사람과, 뻔한 다음곡을 싫어하는 사람을 동시에 배려 |
| 핵심 기술 | 다국어 아티스트 검색 | 한국어 표기로 원어(가나·한자·로마자) 아티스트를 찾을 수 있도록 별칭(별명) 테이블을 함께 매칭한다 (예: "요네즈 켄시" → 米津玄師). | Roon의 다국어 지원을 참고. ⚠ 완전 자동 음역(발음 변환) 엔진이 아니라 별칭 DB 기반 — 태그·관리자 도구로 확장 |
| 핵심 기술 | 위키백과 아티스트 이력 | ko.wikipedia 우선, 없으면 en.wikipedia로 폴백해 짧은 이력 요약과 출처 링크를 라이너 패널에 보여준다. | Roon이 위키피디아를 크롤링해 아티스트 소개를 제공하는 방식을 참고. 저작권상 전문 복제 없이 짧은 발췌 + 출처만 |
| 유틸리티 | 라이브러리 통합 | 로컬 폴더/NAS(FLAC, ALAC, WAV, AIFF, DSD/DSF/DFF, 선택적 MP3/AAC) 스캔. Tidal/Qobuz 등 스트리밍 계정 연동(토큰은 Core 보안 저장). 동일 앨범의 로컬/스트리밍 버전을 하나로 병합 표시. | 스트리밍 SDK는 어댑터로 격리 |
| 유틸리티 | 출력 엔드포인트 관리 | USB DAC, WASAPI/ASIO Exclusive, 네트워크 Output 앱, (향후) AirPlay 계열을 Output 노드로 등록. 기기 능력(포맷, 볼륨, 레이턴시)을 Core에 광고. | Control은 오디오를 재생하지 않음 |
| 유틸리티 | 멀티 디바이스 존 (싱글 플레이 전용) | 내가 가진 여러 출력기기를 하나의 존(Zone)으로 묶어 Sync(전원 동시 재생) 또는 Independent(기기마다 다른 곡)로 운영한다. | Roon의 Zone 그룹핑을 참고. 멀티유저 라운지가 아니라 1인 청취자의 다중 기기 관리 |
| 유틸리티 | 라운지 생성/참여 | 룸 ID, 초대 코드, 친구 세션 목록. 입장 시 Output 능력 협상(공통 포맷 교집합). 실패 시 “이 룸은 DSD256 고정 — 기기가 지원하지 않음”을 명확히 표시. | 모드: Open / Invite / Host Queue / Audiophile |

| 유틸리티 | 동기화 가사 | 재생 `media_time`에 LRC/임베디드 가사를 정렬. 룸 전원에게 동일 하이라이트. 가사 없는 곡은 라이너/웨이브폼만. | 소셜 레이어, 오디오 경로와 무관 |
| 유틸리티 | 세션 아카이브 | 종료 시 “이번 라운지를 저장할까요?” 동의. 저장 시 트랙 목록, 타임스탬프 코멘트, 반응(♥), 재생 구간 히트를 개인 라이브러리에 기록. 미동의 시 휘발. | 개인 데이터 / 룸 정책 분리 |
| 유틸리티 | 세션 → 플레이리스트 | 아카이브에서 “좋았던 곡”(♥, 코멘트, 완청)을 모아 개인 플레이리스트 생성. 소스(로컬/스트리밍) 링크 유지. | 내보내기 M3U/로컬 스마트 리스트 |
| 유틸리티 | 청음 히스토리 | 개인이 들은 곡·룸·날짜 타임라인. 히스토리에서 다시 재생 또는 친구에게 세션 요약 공유(트랙 식별자만, 파일 재배포 아님). | 저작권: 식별자·메타만 공유 |
| 편의 기능 | 크로스 디바이스 Control | PC/Mac/모바일 Control은 Core에만 접속. 화면 렌더링과 입력만 처리. 동일 정보 구조(아트, 큐, 룸 상태). | 장기: 자체 UI 엔진. 현재: Avalonia |
| 편의 기능 | 앨범 아트 퍼포먼스 | 대형 아트 그리드 스크롤 목표 60fps. 디코드·스케일은 Core 또는 Control 백그라운드 캐시. | OpenGL/Skia 경로 예정 |
| 편의 기능 | DSP 프리셋 | 헤드폰/스피커/룸 IR 프리셋. 라운지 호스트가 “룸 DSP 고정” 가능. Audiophile Mode 기본값: DSP Off. | |
| 편의 기능 | 포맷·품질 배지 | 현재 경로가 Bit-perfect인지, SRC가 있는지, 스트리밍 Max/Hifi인지 상시 표시. | 신뢰 UI |
| 인터랙션 | 최다 반응 구간 (리액션 히트맵) | 마음에 드는 파트에 이모지로 반응한다. 곡당 유저당 최대 3번, 이모지는 하트·축포·박수·불꽃(❤️🎉👏🔥)으로 제한해 혐오·불쾌 표현을 막는다. 전체 재생 이력에 걸쳐 반응이 몰린 구간을 시크바 위 히트맵으로 보여준다. | 유튜브의 "가장 많이 다시 본 구간"을 참고. 아티스트 입장에서는 어느 파트가 반응이 좋은지 확인하는 약식 여론조사 역할도 한다 |
| 인터랙션 | 타임스탬프 코멘트 | 재생 위치(ms)에 짧은 감상 핀. 룸 타임라인에 표시, 클릭 시 해당 구간으로 시킹은 **호스트 정책**에 따름(Audiophile/Host Queue는 시킹 제한 가능). | 핀은 메타, 오디오 아님 |

| 인터랙션 | 뮤지션 관계도 | 아티스트 그래프를 Control에서 탐색. 룸에서 “이 연주자 따라가기”로 다음 큐 후보를 제안(호스트 승인). | 로컬 그래프 쿼리 |

## 3. UI/UX 디자인 및 시각적 가이드

사용자에게 전달될 시각적 인상과 인터페이스의 일관성을 정의한다. 참고 이미지는 Roon UI(온보딩·Home·Genres 화면)이다.

### 시스템 컬러 가이드

| 토큰 | 값 | 용도 |
| --- | --- | --- |
| Main | `#FFFFFF` (라이트) / `#121317` (다크) | 기본 배경색 |
| Point | `#6D6DF6` (라이트) / `#8F8FF8` (다크) | 브랜드 강조색 — 인디고/페리윙클, Roon 참고 이미지의 포인트컬러 계열 |
| Line | `#E6E7EC` / `#2B2E36` | 구분선·테두리 |
| Warn | `#D9762F` / `#E39A5C` | 경고·핀 마커 |

### 디자인 컨셉

- **미니멀리즘**: 화이트(라이트) 배경 기본, 여백을 넉넉히 두고 카드·그리드 중심 레이아웃.
- **다크모드 최적화**: 시스템 설정(`prefers-color-scheme`) 자동 반영 + 수동 토글. 색상은 CSS 변수 하나로 라이트/다크 동시 대응.
- **신뢰 가능한 상태 표시**: Bit-perfect 여부, 동기화 오프셋 등 오디오 경로 상태를 배지로 상시 노출(Roon의 "지금 무엇이 재생 중인가"에 대한 투명성 참고).

### 주요 컴포넌트

| 컴포넌트 | 스타일 |
| --- | --- |
| 버튼 | 알약형(pill), 기본은 아웃라인(ghost), 강조 액션만 포인트컬러 채움(primary) |
| 카드 | 둥근 모서리(12px), 은은한 테두리, 호버 시 그림자 상승 |
| 모달/패널 | 배경과 톤을 분리한 패널(`--panel2`) 위에 얹어 위계를 표현 |
| 시크바 | 얇은 트랙 + 포인트컬러 채움 + 핀 마커 + 반응 히트맵 바 |

## 4. 비기능 요구사항

| 항목 | 요구 |
| --- | --- |
| 음질 | 소셜 기능 ON이어도 오디오 콜백 지터에 영향을 주지 않을 것. 측정 가능한 콜백 기한(ASIO/WASAPI Exclusive). |
| 동기화 | LAN 목표: 가청 오프셋 &lt; 5ms. 측정 UI에서 오프셋·지터 표시. |
| 확장 | Core 1 : Control N : Output M. Control 없이도 Output+Core로 재생 가능. |
| 보안 | 룸은 인증된 세션. 음원 파일은 피어에게 재배포하지 않음. 스트리밍은 각 클라이언트의 라이선스/토큰으로 재생하거나, 정책상 **호스트 소스 → 암호화 전송**(라이선스 허용 범위 내에서만, 미허용 시 각자 구독 재생 + 클럭만 동기화). |
| 라이선스 분기 | **A. 각자 재생 + 클럭 싱크**(스트리밍 권장). **B. Core 팬아웃**(로컬 파일, 개인 라운지, 약관 준수). 구현은 어댑터로 분리. |
| UX 일관성 | 플랫폼별 픽셀 단위 동일 UI를 장기 목표로 함. |
